# План: Оптимизация VDO_FILE.read() — кэширование файлового дескриптора

## Проблема

`VDO_FILE.read()` (строки 211–220) открывает и закрывает файл при **каждом** вызове:

```python
def read(self, offset: int, size: int) -> bytes:
    with open(self.file_path, "rb") as f:
        f.seek(offset)
        return f.read(size)
```

При парсинге N блоков → N open/close системных вызовов. Для базы из 500 блоков — 500 открытий файла.

**Критический путь:** `VDO_FILE.get_block()` → `block_base.__init__()` → `self.vdo.read(offset, size)`.
Каждый блок вызывает `read()` минимум 1 раз (чтение буфера), плюс дополнительные вызовы для метаданных.

## Решение: Lazy-кэш файлового дескриптора

### Что меняется

Добавляем в `__slots__` два атрибута и модифицируем `read()`:

| Новый слот | Назначение |
|---|---|
| `_file_handle` | Кэш открытого `file` объекта (None = не открыт) |
| `_file_closed` | Флаг принудительного закрытия (для явного `close()`) |

### Детали реализации

#### 1. Обновить `__slots__` VDO_FILE (строка 118)

```python
__slots__ = (
    "file_path",
    "is_empty",
    "is_single",
    "filename",
    "QGISvdoGroupName",
    "_initialized",
    "dbrev",
    "segsize",
    "file_size",
    "_file_handle",    # ← новый: кэш open()
    "_file_closed",    # ← новый: флаг закрытия
)
```

#### 2. Инициализация в `__new__` и `__init__`

В `__new__` (после строки 161):
```python
obj._file_handle = None
obj._file_closed = True
```

В `__init__` — только для валидного файла (после строки 199):
```python
# Для пустого синглтона дескриптор не нужен
if not self.is_empty:
    self._file_handle = None
    self._file_closed = True
```

#### 3. Заменить `read()` (строки 211–220)

```python
def read(self, offset: int, size: int) -> bytes:
    """Чтение блока байт заданной длины по указанному смещению.
    
    Использует кэшированный файловый дескриптор для избежания
    повторных open/close при множественных чтениях.
    """
    if self.is_empty or size <= 0 or (offset + size) > self.file_size:
        return EMPTY_BUFFER
    
    try:
        # Lazy open: открываем файл при первом чтении
        if self._file_handle is None or self._file_closed:
            self._file_handle = open(self.file_path, "rb")
            self._file_closed = False
        
        self._file_handle.seek(offset)
        return self._file_handle.read(size)
    except (OSError, FileNotFoundError):    # pragma: no cover
        self._file_closed = True
        if self._file_handle:
            self._file_handle.close()
            self._file_handle = None
        return EMPTY_BUFFER
```

#### 4. Добавить метод `close()` (после строки 220)

```python
def close(self) -> None:
    """Явно закрыть кэшированный файловый дескриптор."""
    if self._file_handle and not self._file_closed:
        self._file_handle.close()
        self._file_handle = None
        self._file_closed = True
```

#### 5. Добавить `__del__` для безопасности (после `close()`)

```python
def __del__(self) -> None:
    """Гарантируем закрытие дескриптора при сборке мусора."""
    self.close()
```

## Что НЕ меняется

- `EMPTY_BUFFER` и константы — без изменений
- `_validate_file()` — использует локальный `with open()`, не затрагивается
- `read()` возвращает `bytes` — тип возврата тот же
- API совместимость — все публичные методы сохраняют сигнатуру

## Trade-offs

| Аспект | Было | Станет |
|---|---|---|
| Open/close при парсинге 500 блоков | 500 × open + 500 × close | 1 × open + 1 × close (или явный close()) |
| Память на дескриптор | 0 | ~8 КБ (OS-уровень) |
| Утечка дескриптора при ошибке | Нет (each read is isolated) | Нет (`__del__` гарантирует cleanup) |
| Thread safety | N/A (per-instance) | N/A (per-instance) |

## Тестирование

После изменений проверить:
1. `VDO_FILE()` — пустой синглтон, без дескриптора
2. `VDO_FILE(path)` — валидный файл, дескриптор открывается лениво
3. Множественные `read()` — дескриптор переиспользуется
4. `close()` — дескриптор закрывается
5. Повторный `read()` после `close()` — дескриптор открывается заново
6. `__del__` — дескриптор закрывается автоматически
