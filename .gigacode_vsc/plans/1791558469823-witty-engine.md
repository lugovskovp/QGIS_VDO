# План оптимизации быстродействия bitstream.py

## Анализ производительности

`bitstream.py` — критический путь плагина: распаковка geo-блоков типов 0x14–0x1E из архивов CF=1. Каждый блок содержит тысячи вертексов, полигонов и полилиний. Распаковка вызывается для каждого geo-блока при загрузке карты.

## Батарея №1: `pop()` — главный узел (ОЖИДАЕТСЯ: ×3–5 ускорение)

### Проблема
Метод `pop()` (строка 769–775) вызывает **десятки тысяч раз** за одну распаковку. Каждый вызов:
1. Срезает bitarray: `self.buffer[:qty_bits]` — создаёт новый объект
2. Пересоздаёт буфер: `self.buffer = self.buffer[qty_bits:]` — **полное копирование** оставшихся бит
3. `ba2int()` — вызов функции на каждом результате

### Решение: смещаемый указатель (index-based) вместо сдвига буфера

```python
class bitstream:
    def __init__(self, archived_bock):
        # ... существующий код ...
        self.buffer = bitarray(buffer=arc, endian='big')
        self._buf_idx = 0  # новый: индекс в битах
        self._buf_bytes = bytes(self.buffer)  # превращаем в bytes для быстрого доступа
    
    def pop(self, n: int) -> int:
        """Извлечь n бит из начала буфера, вернуть int. O(1) на вызов."""
        if n == 0:
            return 0
        idx = self._buf_idx
        self._buf_idx += n
        # Извлекаем n бит из bytes-буфера
        byte_start = idx // 8
        bit_offset = idx % 8
        val = 0
        for i in range(n):
            byte_pos = byte_start + (bit_offset + i) // 8
            bit_pos = 7 - ((bit_offset + i) % 8)
            if self._buf_bytes[byte_pos] & (1 << bit_pos):
                val = (val << 1) | 1
            else:
                val = val << 1
        return val
```

**Альтернатива** (проще, но менее эффективно): использовать `int.from_bytes(self._buf_bytes[idx//8 : (idx+n+7)//8])` с маскированием.

**Ожидаемый эффект:** удаление создания bitarray на каждый вызов + удаление копирования буфера.

## Батарея №2: Кэширование констант-битмассок (×1.5–2 ускорение)

### Проблема
Строки 43–46 + многократные сравнения:
```python
CONST_BA_11 = bitarray([1, 1])
CONST_BA_10 = bitarray([1, 0])
CONST_BA_01 = bitarray([0, 1])
CONST_BA_00 = bitarray([0, 0])
```
Каждый вызов `self.pop(1) == bitarray([1])` создаёт временный bitarray и сравнивает.

### Решение
Заменить все сравнения на `self.pop(1) != 0` или `self.pop(1) == 1`:
```python
# Вместо:
if self.pop(1) == bitarray([1]):
# На:
if self.pop(1):  # pop возвращает int, 0 = False, 1 = True
```

## Батарея №5: `struct.pack` → `int.to_bytes()` (×1.1–1.3 ускорение)

### Проблема
Многократные вызовы `struct_WORD.pack()` в циклах распаковки:
- Строка 524: `struct_WORD.pack(prev_x)`
- Строка 532: `struct_WORD.pack(prev_x) + struct_WORD.pack(prev_y)`
- Строка 885: `struct_WORD.pack(vrtx_offset)`

### Решение
```python
# Вместо: struct_WORD.pack(val)
# На: val.to_bytes(2, 'big')
```
`int.to_bytes()` быстрее `struct.Struct.pack()` для простых случаев.

## Батарея №6: `LOOKUP_CHAR_BYTES` → list/array (×1.2 ускорение)

### Проблема
Строка 689: `LOOKUP_CHAR_BYTES[prefix.to01()]` — lookup по строковому ключу в dict.

### Решение
Преобразовать в массив по индексу:
```python

LOOKUP_CHAR_BYTES = bytearray([
    ord('a'),   # '000' = 0
    ord('e'),   # '001' = 1

    ord('d'),   # '10001' = 17
    ord('g'),   # '10010' = 18
    ord('h'),   # '10011' = 19
    ord('i'),   # '10100' = 20
    ord('l'),   # '10101' = 21
    ord('n'),   # '10110' = 22
    ord('o'),   # '10111' = 23
])
# В bitstream.py:
bin_str += bytes((LOOKUP_CHAR_BYTES[int(prefix.to01(), 2)],))
```

## Риски

1. **Index-based pop** — требует тщательного тестирования, т.к. меняет фундаментальную модель работы с буфером
2. **LOOKUP_CHAR_BYTES → bytearray** — нужно убедиться, что все индексы корректны (sparse array → dense)
3. `int.to_bytes()` — проверить, что порядок байт ('big') совпадает с ожидаемым
